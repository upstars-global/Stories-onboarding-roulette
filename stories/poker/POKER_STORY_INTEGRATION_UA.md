# Документація Poker Stories

## Загальний опис

Poker Stories — онбординг-сторіс, яка пояснює гравцеві суть покеру (Casino Hold'em) і показує хід гри: від ставки Ante до виплати. Сторіс складається з 7 слайдів, доступна 6 мовами та відкривається на сайті в iframe.

Кожен слайд — це відео на весь кадр і текст поверх нього: назва сторіс, рядок розділу, заголовок, опис і кнопка «Play Poker». Текст друкується одночасно з відтворенням відео; слайд завершується разом із відео, після чого відкривається наступний.

Проєкт побудований на Vue 3 + Vite. Результат збірки — статичні файли, які розміщуються на CDN.

## Посилання та вбудовування

### Адреса

Сторіс розміщується за тією ж схемою, що й попередні (roulette, blackjack, baccarat, game-shows):

```
https://cdn-wl.s3.amazonaws.com/common/stories/poker/index.html
```

### Приклад повного посилання

```
https://cdn-wl.s3.amazonaws.com/common/stories/poker/index.html?user_language=en&game_link=live%2Fcategories%2Fpoker&end_link=live%2Fcategories%2Fpoker
```

### Вбудовування в iframe

```html
<iframe
  src="https://cdn-wl.s3.amazonaws.com/common/stories/poker/index.html?user_language=en&game_link=live%2Fcategories%2Fpoker"
  width="100%"
  height="100%"
  allow="autoplay"
></iframe>
```

Відео запускається автоматично без звуку. Звук вмикає користувач кнопкою в шапці сторіс. Музика грає з окремого файлу й не переривається під час переходу між слайдами (див. «Музика»).

## Query параметри

Сторіс отримує параметри від батьківського сайту через URL.

| Параметр | Тип | Опис | Приклад |
|----------|-----|------|---------|
| `user_language` | String | Мова текстів: `en`, `de`, `fr`, `it`, `es`, `pt`. Значення передається малими літерами. Якщо параметр відсутній або мова не підтримується, використовується `en` | `user_language=de` |
| `game_link` | String | Посилання, на яке веде кнопка «Play Poker». Якщо параметр відсутній, використовується `live/categories/poker` | `game_link=live%2Fcategories%2Fpoker` |
| `end_link` | String | Посилання для переходу після закриття сторіс. Якщо параметр відсутній, після закриття перехід не виконується | `end_link=live%2Fcategories%2Fpoker` |

До `end_link` автоматично додаються UTM-мітки:

```
utm_source=site&utm_medium=story&utm_campaign=poker_story
```

Параметри `story`, `user_currency`, `stories_total` і `discover_link` приймаються, але на показ цієї сторіс не впливають: сторіс завжди починається з першого слайда, суми в текстах наведено в EUR, рядка з додатковим посиланням під кнопкою немає.

## Події для батьківського сайту

Сторіс надсилає події батьківському сайту через `window.parent.postMessage(message, '*')`. Кожна подія — текстовий рядок.

### Навігаційні події

| Подія | Коли відправляється |
|-------|---------------------|
| `click_forward` | Перехід на наступний слайд: тап у правій половині екрана, кнопка-стрілка на десктопі або автоматичний перехід після завершення відео |
| `click_backward` | Перехід на попередній слайд: тап у лівій половині екрана або кнопка-стрілка на десктопі |

### Контрольні події

| Подія | Коли відправляється |
|-------|---------------------|
| `click_pause` | Пауза: утримання пальця на екрані довше 350 мс, кнопка паузи на десктопі, поява попередження про горизонтальну орієнтацію |
| `click_play` | Відтворення відновлено після паузи або розпочато кнопкою Play, якщо браузер заблокував автозапуск |
| `mute_video` | Звук вимкнено |
| `unmute_video` | Звук увімкнено |

### Події закриття та переходів

| Подія | Коли відправляється |
|-------|---------------------|
| `close` | Натиснуто кнопку закриття |
| `start_game_btn` | Натиснуто кнопку «Play Poker» |
| `go_to_link:[URL]` | Через 300 мс після `close` — з адресою `end_link` та UTM-мітками (лише якщо `end_link` передано); через 300 мс після `start_game_btn` — з адресою `game_link` |

### Аналітичні події

| Подія | Коли відправляється |
|-------|---------------------|
| `opened_story:1` | Відкрито останній, сьомий слайд |

### Обробка подій у батьківському застосунку

```javascript
window.addEventListener('message', function (event) {
  if (typeof event.data !== 'string') return;

  if (event.data === 'close') {
    // закрити iframe зі сторіс
  } else if (event.data === 'start_game_btn') {
    // гравець натиснув «Play Poker»
  } else if (event.data.startsWith('go_to_link:')) {
    const url = event.data.replace('go_to_link:', '');
    // виконати перехід за url
  }
});
```

## Відео

### Розміри

Кожне відео підготовлено у двох розмірах: 1080×1920 і 720×1280. Розмір обирається за кількістю фізичних пікселів, які відео займає на екрані:

- на мобільному пристрої — ширина екрана, помножена на щільність пікселів;
- на десктопі — ширина картки сторіс (432/900 висоти вікна), помножена на щільність пікселів.

Якщо відео займає до 800 фізичних пікселів у ширину, відтворюється версія 720×1280, інакше — 1080×1920. Швидкість з'єднання на вибір не впливає.

| Пристрій | Ширина відео на екрані | Розмір файлу |
|----------|------------------------|--------------|
| Телефон зі щільністю 2 (360×640, iPhone SE) | 720–750 px | 720 |
| Десктоп зі звичайним монітором (1440×900, 1920×1080) | 430–520 px | 720 |
| Сучасні iPhone і Android зі щільністю 3 | 1080–1320 px | 1080 |
| MacBook, монітор 4K | 830–1380 px | 1080 |

Розмір визначається під час відкриття сторіс і при зміні розміру вікна; новий розмір застосовується з наступного слайда. Поточне відео не перезавантажується.

### Формати

Кожен розмір підготовлено в чотирьох форматах. Браузер отримує всі чотири джерела та відтворює перше, яке підтримує.

| Порядок | Формат | Файл 1080 | Файл 720 |
|---------|--------|-----------|----------|
| 1 | AV1 | `story_N-av1.mp4` | `story_N-720-av1.mp4` |
| 2 | H.265 | `story_N-h265.mp4` | `story_N-720-h265.mp4` |
| 3 | H.264 | `story_N-h264.mp4` | `story_N-720-h264.mp4` |
| 4 | WebM (VP9) | `story_N.webm` | `story_N-720.webm` |

Типи джерел:

| Формат | Тип джерела 1080 | Тип джерела 720 |
|--------|------------------|-----------------|
| AV1 | `video/mp4; codecs="av01.0.08M.08"` | `video/mp4; codecs="av01.0.05M.08"` |
| H.265 | `video/mp4; codecs="hvc1.1.6.L120.90"` | `video/mp4; codecs="hvc1.1.6.L93.90"` |
| H.264 | `video/mp4; codecs="avc1.640028"` | `video/mp4; codecs="avc1.64001F"` |
| WebM (VP9) | `video/webm; codecs="vp09.00.40.08"` | `video/webm; codecs="vp09.00.31.08"` |

AV1 пропонується лише пристроям з апаратним декодуванням цього формату; решта пристроїв починає з H.265.

Параметри всіх файлів: 30 кадрів за секунду, без звукової доріжки: звук сторіс грає з окремого файлу (див. «Музика»).

| 2 | 2,43 / 1,46 | 3,10 / 1,79 | 4,41 / 2,58 | 3,60 / 1,96 |
| 3 | 0,24 / 0,16 | 0,44 / 0,24 | 0,58 / 0,37 | 0,36 / 0,21 |

| 5 | 0,47 / 0,31 | 0,65 / 0,39 | 1,00 / 0,54 | 0,68 / 0,43 |
| 6 | 0,80 / 0,55 | 1,14 / 0,70 | 1,82 / 0,96 | 1,12 / 0,70 |

Користувач завантажує файли лише одного розміру й одного формату. Наступне відео завантажується в пам'ять заздалегідь, поки відтворюється поточне, і після переходу починається одразу.

## Музика

Звук сторіс — одна музична доріжка на всі 7 слайдів, окремо від відео. Під час переходу між слайдами музика не переривається.

| Файл | Формат | Розмір |
|------|--------|--------|
| `soundtrack.m4a` | HE-AAC, 64 кбіт/с | 1,04 МБ |
| `soundtrack.webm` | Opus, 64 кбіт/с, для браузерів без AAC | 1,08 МБ |

- Музика завантажується заздалегідь, у фоні, у перші секунди показу, тож звук вмикається одразу. Якщо звук увімкнули, поки музика ще завантажується, сторіс чекає її, коли вона встигає завантажитися за 1,5 секунди, інакше вмикає музику з мережі. Браузер завантажує один файл із двох — той, який підтримує.
- Музика йде поруч із відео з розбіжністю до 2 секунд і не прискорюється й не сповільнюється. Поки наступне відео завантажується, музика грає далі. Якщо розбіжність стає більшою, а також після тапу чи стрілки музика переходить на потрібне місце на ціле число тактів, тож ритм не збивається.
- Пауза, утримання екрана, вимкнення звуку й закриття сторіс зупиняють музику. На прихованій вкладці музика не грає.
- Події `mute_video` і `unmute_video` надсилаються, як і раніше.

## Технічні деталі

### Управління

- **Мобільні пристрої**: тап у правій або лівій половині екрана — наступний або попередній слайд; утримання — пауза.
- **Десктоп**: кнопки-стрілки, кнопка паузи.
- **Звук**: кнопка в шапці сторіс; за замовчуванням звук вимкнено; музика не переривається між слайдами.

### Адаптивність

- Екран зі співвідношенням сторін 9:16 і десктоп: кадр відповідає макету.
- Екран, вищий за 9:16: відео займає всю ширину і притиснуте до нижнього краю, над ним — фон кольору верхнього краю відео; боки відео не обрізаються.
- Екран, нижчий за 9:16: відео займає всю ширину, зверху і знизу обрізається порівну.
- У горизонтальній орієнтації на мобільному пристрої показується прохання повернути телефон, відтворення ставиться на паузу.

## Розміщення на CDN

На CDN розміщується вміст папки `dist/poker/` без змін: `index.html` і папка `assets/` з 56 відеофайлами (7 слайдів × 2 розміри × 4 формати), двома файлами музики, скриптом і стилями.

Вимоги до роздачі файлів:

- `Content-Type: video/mp4` для файлів `.mp4`, `video/webm` для файлів `.webm` і `audio/mp4` для файлу `.m4a`;
- підтримка часткових запитів (`Accept-Ranges: bytes`).

## Збірка

Усі файли сторіс лежать у папці `stories/poker/`: тексти (`stories.json`), кольори та розміри шрифту (`story.scss`), іконка, відео, звіт про відео і музика (`audio/`). Код сторіс спільний для всіх сторіс проєкту.

```bash
# Встановлення залежностей
npm install

# Режим розробки
npm run dev poker

# Збірка для продакшену — результат у dist/poker/
npm run build poker

# Попередній перегляд збірки
npm run preview poker
```

## Підготовка відео

Відеофайли вже лежать у репозиторії, у `stories/poker/videos/`. Їх створює скрипт `scripts/encode-story-videos.mjs` з вихідних файлів дизайнера:

```bash
npm run video:encode -- --story poker --src <папка з вихідними файлами>
```

- Вихідні файли — по одному MP4 на слайд, 1080×1920, з назвою за номером слайда: `1.mp4`, `2.mp4`. Повторна версія називається `2_1.mp4`; з кількох версій береться найновіша. Інші файли в папці пропускаються.
- Скрипт створює обидва розміри і всі чотири формати та підбирає стиснення окремо для кожного відео: найменший файл, якість якого не нижча за поріг. Відео обробляються по одному, щоб не перевантажувати комп'ютер.
- Сторіс знаходить файли за назвою кліпу (`story_1`, `story_2`…), тому шляхи до відео в `stories.json` не прописуються.
- Результати записуються у `stories/poker/video-report.json`: вага, оцінка якості, тип джерела кожного файлу.
- Потрібен ffmpeg з кодеками AV1, H.265, VP9, H.264, Opus і VMAF (`brew install ffmpeg`).

Музику створює скрипт `scripts/build-story-soundtrack.mjs` зі звуку тих самих вихідних файлів. Запускається після відео:

```bash
npm run audio:build -- --story poker --src <папка з вихідними файлами>
```

- Скрипт склеює звук семи відео в одну доріжку, прибирає звук із самих відео і записує в `stories/poker/audio/` два файли музики та `soundtrack.json` — де в доріжці починається кожен слайд.
- На трьох стиках вихідних відео бракує 7–8 кадрів музики. Скрипт відновлює їх із такого самого місця мелодії, яка повторюється, тож ритм на стиках не збивається.
- Відео без звуку скрипт записує так, щоб кожен кадр лежав у файлі окремим блоком, як у відео зі звуком. Інакше Safari перед показом чекає, поки завантажиться великий шматок файлу, і на iPhone кожен перехід затримується на 1,5–5 секунд. Збірка перевіряє це для кожного відео.
- Після нового кодування відео скрипт запускається знову. Доки музика не відповідає відео, збірка зупиняється з підказкою.

## Перевірка

- Сторіс відкривається за посиланням із `user_language` для кожної з 6 мов; тексти відповідають мові.
- Відео запускається автоматично без звуку; кнопка звуку вмикає і вимикає музику.
- Під час переходу між слайдами — автоматично, тапом і стрілками — музика не переривається; пауза й утримання екрана зупиняють її разом із відео.
- На телефоні зі щільністю 2 і на десктопі зі звичайним монітором відтворюється файл з `-720` у назві; на телефоні зі щільністю 3 — файл без `-720`.
- Слайди перемикаються тапом, стрілками та автоматично після завершення відео; смужки прогресу заповнюються.
- На слайді 4 речення опису з'являються разом із картами.
- Кнопка «Play Poker» надсилає `start_game_btn` і `go_to_link` з адресою `game_link`.
- Кнопка закриття надсилає `close` і, якщо передано `end_link`, `go_to_link` з адресою та UTM-мітками.
- На останньому слайді надсилається `opened_story:1`.
