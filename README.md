# Онбординг-сторіс

Код сторіс один на всі сторіс. Кожна сторіс — окрема папка в `stories/`: тексти, відео, іконка й налаштування вигляду. Одна збірка робить одну сторіс у папку `dist/<назва>/`, вміст якої розміщується на CDN у `common/stories/<назва>/`.

## Команди

```bash
npm install                    # один раз після клонування

npm run dev poker              # локальний сервер, відкривається і з телефона в тій самій мережі
npm run build poker            # перевірка типів і збірка в dist/poker/
npm run preview poker          # перегляд зібраної dist/poker/

npm run video:encode -- --story poker --src <папка з відео дизайнера>
npm run audio:build -- --story poker --src <папка з відео дизайнера>   # музика окремим файлом, після відео
```

Поки в `stories/` одна сторіс, назву можна не вказувати. Додаткові параметри Vite пишуться після назви: `npm run preview -- poker --host --port 4310`.

## Папка сторіс

| Файл | Що в ньому |
|------|------------|
| `stories.json` | Тексти слайдів 6 мовами, назва сторіс, текст кнопки, посилання на гру та UTM-кампанія |
| `story.scss` | Колір фону над відео, розміри заголовка й опису для кожної мови |
| `icon.webp` | Іконка в шапці сторіс |
| `videos/` | Відео слайдів, які створює `npm run video:encode` |
| `audio/` | Необов'язково: музика сторіс одним файлом, яку створює `npm run audio:build`. Без цієї папки звук іде з відео |
| `video-report.json` | Вага та якість кожного відеофайлу |
| `*_INTEGRATION_UA.md`, `.docx` | Документ для сайту |

Решта (поведінка, верстка, вибір відео під екран) — спільний код у `src/`.

### stories.json

| Поле | Що задає |
|------|----------|
| `stories.title` | Назва сторіс у шапці та у вкладці браузера (`en`) |
| `stories.items[]` | Слайди по порядку: `topText` (рядок під назвою), `header`, `description` |
| `stories.items[].video` | Назва кліпу, наприклад `story_3`. Якщо поле відсутнє — `story_<номер слайда>` |
| `stories.items[].descriptionSteps` | Необов'язково: опис друкується частинами, кожна з певної секунди відео |
| `ui.ctaButton.text` | Текст кнопки 6 мовами |
| `ui.orientationLock` | Прохання повернути телефон 6 мовами |
| `links.game` | Куди веде кнопка, якщо сайт не передав `game_link` |
| `links.utmCampaign` | Мітка `utm_campaign` для посилання після закриття, наприклад `poker_story` |

Шляхи до відео не прописуються: сторіс знаходить файли в `videos/` за назвою кліпу. Збірка зупиняється з переліком файлів, яких бракує.

## Нова сторіс

1. Скопіювати `stories/poker` у `stories/<назва>`, видалити з копії `videos/`, `video-report.json` і документ покеру.
2. У `stories.json` замінити тексти, назву, текст кнопки, `links.game` і `links.utmCampaign` (`<назва>_story`).
3. У `story.scss` вказати колір верхнього краю відео та розміри шрифту.
4. Замінити `icon.webp`.
5. Створити відео: `npm run video:encode -- --story <назва> --src <папка з відео дизайнера>`.
6. Якщо музика має грати без перерв між слайдами: `npm run audio:build -- --story <назва> --src <папка з відео дизайнера>`.
7. Перевірити: `npm run dev <назва>`.
8. Зібрати: `npm run build <назва>`, розмістити вміст `dist/<назва>/` на CDN.

## Відео від дизайнера

- Один файл MP4 на слайд, 1080×1920, 30 кадрів за секунду, фон усередині кадру (непрозорий).
- Назва — номер слайда: `1.mp4`, `2.mp4`. Повторна версія — `2_1.mp4`; береться найновіша.
- Якість — максимальна: стискає скрипт. Інші файли в папці (.mov, .webm, .xmp) пропускаються.

Скрипт робить кожне відео у двох розмірах (1080 і 720) і чотирьох форматах (AV1, H.265, H.264, WebM) та підбирає стиснення окремо для кожного: найменший файл, якість якого не нижча за поріг. Відео обробляються по одному: розмір 720 для семи відео покеру зайняв близько 40 хвилин, 1080 займає більше. Потрібен ffmpeg (`brew install ffmpeg`).

## Музика окремим файлом

Коли звук лежить у кожному відео, на переході між слайдами він обривається: відео закінчилося — звук теж, а наступний шматок починається тільки після завантаження наступного відео. `npm run audio:build` виносить звук в одну доріжку на всю сторіс, і вона грає без перерв поверх відео.

- Скрипт бере звук тих самих вихідних файлів, що й `video:encode` (список — у `video-report.json`), тож запускається після нього. Якщо поруч із `3.mp4` лежить той самий кліп з нестиснутим звуком (`3-HEVC Alpha 3Mbps.mov`), звук береться з нього.
- Стики склеюються так, щоб ритм ішов далі: якщо на стику бракує кількох кадрів музики, вони відновлюються з такого самого місця мелодії. Що зроблено на кожному стику, скрипт друкує.
- Результат — `audio/soundtrack.m4a` (HE-AAC, 64 кбіт/с) і `audio/soundtrack.webm` (Opus, 64 кбіт/с, для браузерів без AAC) та `audio/soundtrack.json`: де в доріжці починається кожен слайд і довжина такту. Звук із відео прибирається, вони стають легшими.
- Відео без звуку записуються так, щоб кожен кадр лежав окремим блоком (`scripts/mp4-index.mjs`). Так їх пише відео зі звуком, а ffmpeg без звуку збирає кадри в блоки по 1 МБ, і Safari не показує нічого, доки блок не завантажиться: на iPhone кожен перехід затримувався на 1,5–5 секунд. Збірка перевіряє це для кожного відео.
- У сторіс музика вмикається кнопкою звуку і йде поруч із відео з розбіжністю до 2 секунд, без прискорень і сповільнень. Поки наступне відео завантажується, музика грає далі. Якщо розбіжність більша, а також після тапу чи стрілки музика переходить на потрібне місце на ціле число тактів — ритм не збивається. Код — `src/composables/useSoundtrack.ts`.
- Музика і наступне відео завантажуються в пам'ять заздалегідь (`src/composables/useVideoPrefetch.ts`): звук вмикається одразу, а наступний слайд починається без очікування. Safari не використовує те, що завантажено звичайним запитом, тому саме в пам'ять. Музика — близько 1 МБ на дві хвилини, тож завантажується приблизно за секунду. Вона починає завантажуватися, щойно перше відео має 3 секунди запасу; якщо відео не стартує саме (iPhone у режимі енергозбереження показує кнопку відтворення) — після тапу на цю кнопку. Якщо звук увімкнули раніше, ніж музика завантажилася, кнопка звуку сама запускає завантаження і чекає його, поки за швидкістю воно встигає за 1,5 секунди, а інакше грає музику з мережі: в Safari потік із мережі звучить через 1–3 секунди.
- Після нового `video:encode` треба знову запустити `audio:build`: доки музика не відповідає відео, збірка зупиняється з підказкою. Для сторіс з папкою `audio/` скрипт кодування відразу кладе відео без звуку.

## Попередні сторіс

Roulette, Blackjack, Baccarat і Game shows зроблені до цієї схеми й лежать у гілках `stories-onboarding-<назва>`. У них прозорі відео та власна верстка; кожна переноситься в папку окремо, коли в ній знадобляться зміни.
